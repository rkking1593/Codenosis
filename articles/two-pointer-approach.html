Two Pointer Approach — The Art of Shrinking Your Search Space

One technique. Dozens of classic interview problems. Learn how two pointers work, when to reach for them, and how to walk through real problems like a pro.

Y
Yogesh
DSA & Algorithms · Codenosis

The Two Pointer technique is one of those rare algorithmic tools that feels like cheating once you truly understand it. Problems that look like they need nested loops — O(n²) brute force — suddenly collapse into a single O(n) pass. This article covers everything: the intuition, the patterns, step-by-step walkthroughs, and a map of when to actually use it.

What Is the Two Pointer Technique?

At its core, the two pointer approach uses two index variables (pointers) that traverse a data structure — usually an array or string — simultaneously. Instead of checking every pair of elements with two nested loops, you use the positions of these two pointers cleverly so that you only ever do one pass through the data.

The key insight is that in many problems, you can eliminate large chunks of the search space based on a comparison between what the pointers currently point at. This is why the approach is so powerful.

Think of two pointers like two fingers scanning a book — one from the left margin, one from the right. Depending on what each finger sees, you decide which one to move inward. You never need to compare every possible pair of pages.

The Three Main Flavors

Two pointer problems generally come in three setups. Understanding which flavor fits a problem is half the battle.

Opposite Ends (Converging)

Left pointer starts at index 0, right pointer starts at the last index. They move toward each other. Classic for sorted-array pair problems.

Same Direction (Sliding)

Both pointers start at index 0 and move forward. The gap between them forms a window. Classic for subarray/substring problems.

Fast & Slow (Floyd's)

One pointer moves one step at a time; the other moves two. Classic for cycle detection in linked lists.

Multi-array / Two Sequences

One pointer per array. Used to merge or compare two sorted arrays simultaneously. Classic in merge sort and diff algorithms.

Python Code — Two Sum (Sorted)

def two_sum_sorted(nums, target):
    left = 0
    right = len(nums) - 1

    while left < right:
        current_sum = nums[left] + nums[right]

        if current_sum == target:
            # 1-indexed result
            return [left + 1, right + 1]
        elif current_sum < target:
            left += 1   # Need larger sum → move left pointer right
        else:
            right -= 1  # Need smaller sum → move right pointer left

    return []  # No pair found


# Example usage
nums = [2, 7, 11, 15]
target = 9
print(two_sum_sorted(nums, target))  # Output: [1, 2]

Example 2 — Valid Palindrome

Problem: Given a string, check whether it reads the same forwards and backwards (ignoring non-alphanumeric characters and case).

Input: "A man, a plan, a canal: Panama" → Output: True

The two-pointer solution is elegant here. Place one pointer at the very start and one at the very end. Skip any character that isn't a letter or digit. Then compare. If all comparisons match until the pointers cross, it's a palindrome. 

def is_palindrome(s):
    left = 0
    right = len(s) - 1

    while left < right:
        # Skip non-alphanumeric from the left
        while left < right and not s[left].isalnum():
            left += 1

        # Skip non-alphanumeric from the right
        while left < right and not s[right].isalnum():
            right -= 1

        # Compare characters (case-insensitive)
        if s[left].lower() != s[right].lower():
            return False

        left += 1
        right -= 1

    return True


# Example usage
print(is_palindrome("A man, a plan, a canal: Panama"))  # True
print(is_palindrome("race a car"))                       # False

The brute force way would be to strip the string and compare it with its reverse — that works too, but uses O(n) extra space. Two pointers gives us O(1) space and the same O(n) time.

Example 3 — Remove Duplicates from Sorted Array (In-Place)

Problem: Given a sorted array, remove duplicates in-place so that each element appears only once. Return the new length. Do not allocate extra space.

This uses the same-direction flavor — both pointers start at 0, but one (the fast pointer) races ahead while the slow pointer marks where the next unique value should go. 

def remove_duplicates(nums):
    if not nums:
        return 0

    slow = 0  # Points to the last confirmed unique position

    for fast in range(1, len(nums)):
        if nums[fast] != nums[slow]:
            slow += 1
            nums[slow] = nums[fast]  # Write unique value into place

    return slow + 1  # Length of deduplicated portion


# Example usage
nums = [1, 1, 2, 3, 3, 3, 4, 5, 5]
k = remove_duplicates(nums)
print(k)            # 5
print(nums[:k])     # [1, 2, 3, 4, 5]

Example 4 — Container With Most Water

Problem: Given an array height where each element is the height of a vertical line, find two lines that together with the x-axis forms a container that holds the most water.

Key insight: The area = min(height[L], height[R]) × (R - L). We start with the widest possible container (L=0, R=end). To potentially increase the area, we must move the pointer on the shorter side — because keeping the shorter side can never increase the min height, and moving it might find something taller. 

def max_water(height):
    left = 0
    right = len(height) - 1
    max_area = 0

    while left < right:
        # Width is the distance between pointers
        width = right - left
        # Height is limited by the shorter wall
        current_height = min(height[left], height[right])
        area = width * current_height
        max_area = max(max_area, area)

        # Move the shorter side inward to look for a taller wall
        if height[left] < height[right]:
            left += 1
        else:
            right -= 1

    return max_area


# Example usage
height = [1, 8, 6, 2, 5, 4, 8, 3, 7]
print(max_water(height))  # Output: 49

Why move the shorter side? Because if you move the taller side, the width decreases AND the height stays limited by the same shorter side — area can only get worse. Moving the shorter side is the only chance to find a taller wall that could compensate for the reduced width.

When to Apply the Two Pointer Technique

Not every problem needs two pointers — but these are the clearest signal patterns that suggest it's the right tool:

  • The input is sorted (or can be sorted) — Sorted order is what lets you make intelligent decisions about which pointer to move.
  • You need to find a pair or triplet satisfying a condition — Two Sum, Three Sum, pair with max product, etc.
  • You need to check a symmetry property — Palindromes, balanced strings, matching brackets from both ends.
  • You need to partition or filter in-place — Moving zeros to the end, removing duplicates, Dutch National Flag problem.
  • You're optimizing a window or range — Container With Most Water, trapping rainwater, minimum window substring.
  • You're dealing with a linked list cycle or middle — Fast/slow pointer (Floyd's algorithm) finds cycles in O(1) space.
  • You're merging two sorted arrays or sequences — One pointer per array, advance whichever is smaller.

Good Fit

Find if any pair sums to K in a sorted array, check palindrome, merge sorted arrays, detect linked list cycle, remove duplicates in-place.

Not a Fit

Problems needing random access or hash-based lookups, unsorted data where sorting would change the answer, tree/graph traversals where pointers don't apply.

Bonus — 3Sum (Extending Two Pointers)

Two pointers shine even more when extended to three-element problems. For 3Sum, fix one element with a loop, then run two pointers on the rest of the array for each fixed element. 

def three_sum(nums):
    nums.sort()
    result = []

    for i in range(len(nums) - 2):
        # Skip duplicates for the fixed element
        if i > 0 and nums[i] == nums[i - 1]:
            continue

        left = i + 1
        right = len(nums) - 1

        while left < right:
            total = nums[i] + nums[left] + nums[right]

            if total == 0:
                result.append([nums[i], nums[left], nums[right]])
                # Skip duplicates for left and right
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1
            elif total < 0:
                left += 1
            else:
                right -= 1

    return result


# Example usage
nums = [-1, 0, 1, 2, -1, -4]
print(three_sum(nums))  # [[-1, -1, 2], [-1, 0, 1]]

Common Mistakes to Avoid

Applying two pointers to an unsorted array and expecting it to find all pairs — it won't work unless you sort first. The logic of "move left to increase, move right to decrease" only holds in sorted order.

Forgetting the loop termination condition left < right. If both pointers reach the same index, you shouldn't be comparing an element with itself.

Not skipping duplicate values in 3Sum / K-Sum problems — this will give you duplicate triplets in the result set, which is usually incorrect.

Confusing two pointers with sliding window — both use two indices, but in sliding window, you expand one side and contract the other based on a constraint (like sum ≤ k), not a fixed comparison rule.

Wrapping Up

The two pointer technique is not a magic trick — it's a deliberate reduction of the search space. Every time you move a pointer, you're making a guarantee: "I know for certain this region can't hold a better answer." That guarantee comes from the structure of the data (usually sorted order) and the property you're searching for.

Once you internalize that idea, you'll start recognizing two-pointer problems on sight. The pattern shows up constantly in interviews — two sum, palindromes, container problems, deduplication, linked list cycle — and knowing this technique cold is one of the highest-leverage things you can do for your DSA preparation.

Start with the easy problems in the practice table, implement each one from scratch, and trace through your pointer movements manually on paper at least once. That tactile understanding is what makes the technique click.
